# Search Strategy Analysis & Brainstorm

Findings from analyzing two real campaigns side-by-side, plus a proposed redesign of how Google search queries are generated for finding public WhatsApp group invite links.

Audience: anyone working on a lead-gen tool that scrapes the open web for WhatsApp invites. Written in plain language where possible; pipeline-specific terms are explained inline.

---

## TL;DR

1. **Narrow queries beat broad queries.** A campaign with the *narrower* industry term and *fewer* platforms enabled returned **10× more leads** than a campaign with the broader term and more platforms.
2. **Social platforms (LinkedIn, X, Facebook) are bad ROI** for WhatsApp invite hunting — not because scraping is hard, but because the invites mostly aren't there.
3. **Meetup, Eventbrite, Reddit, and (untapped) YouTube + Telegram are where invites actually live.** Public pages, indexed by Google, often with the invite link visible in the snippet itself.
4. The current query generator (single LLM call producing ~30 queries) **doesn't reliably exploit the narrowing operators that work** — `"chat.whatsapp.com"` exact-phrase, quoted industry terms, `site:` operators. Replacing the single call with **(LLM expansion) + (algorithmic combinator)** would 2–3× yield with no extra cost.

## The data — Campaign 2 vs Campaign 3

Both campaigns ran the same pipeline against the same SaaS-related ICP. Same Serper budget, same scoring. Only the **industry term** and the **enabled platforms** differed.

| | Campaign 2 | Campaign 3 |
|---|---|---|
| Industry term | `"SaaS company owners"` (broad phrase) | `"SaaS"` (narrow term) |
| Locations include | US, UK, Dubai | US, UK, Dubai |
| Locations exclude | India, Indian | India, Indian |
| Platforms enabled | reddit, web, meetup, eventbrite, **facebook, linkedin, twitter, x** | reddit, web, meetup, eventbrite |
| Queries generated by LLM | ~30 | ~30 |
| **Leads found** | **2** (1 facebook, 1 twitter) | **20** (all meetup.com) |

That's the headline result: Campaign 3 produced 10× the leads despite using *fewer* platforms.

## Why social platforms underperformed

Even though Campaign 2's LLM dutifully generated `site:facebook.com`, `site:linkedin.com`, `site:twitter.com`, and `site:x.com` queries, they returned almost nothing useful. There are platform-specific reasons:

- **LinkedIn** — most content is auth-walled. Google indexes very little. The platform's algorithm actively penalizes posts containing external links, so users almost never share `chat.whatsapp.com/...` links there. Even when a public LinkedIn post exists, the snippet is too short to contain a full invite URL.
- **Facebook** — group/post pages are private by default. Public pages exist but rarely contain WhatsApp invites in their visible meta-description (which is what Google snippets pull from).
- **X / Twitter** — public tweets *are* indexed, but the 280-character text is mostly truncated by the time it reaches Google's snippet, so the invite URL gets cut off. Since 2023 Twitter has also reduced Google's crawl access.
- **Reddit** — many invite links are in private subreddits or banned communities. Comment threads (where invites often appear) get less Google snippet coverage than top-level posts.

In all four cases, even when our pipeline knew about a candidate URL, **fetching the page would fail** (LinkedIn / FB / X actively block scrapers; Firecrawl can't bypass that for those hosts). The only way to extract an invite from these is the snippet-hit shortcut — and the snippets don't have invites in them.

## Why meetup.com dominates

- **Pages are fully public** — Google indexes them, Firecrawl fetches them.
- **Meetup organizers commonly drop a WhatsApp invite** in the event description as a "join the community" link.
- Because meetup pages are content-rich, **Google's snippet often includes the invite URL verbatim**, so the pipeline grabs it via the cheap snippet-hit path with zero Firecrawl credit cost.
- Niche meetup groups (e.g. "AI Founders Dubai") are exactly the kind of small focused community that matches an ICP without keyword overlap with bigger noisier groups.

Eventbrite is a softer version of the same pattern — public, indexable, occasionally has invites in event descriptions, but a notch lower in density than Meetup.

## How Google search queries work in this pipeline (today)

For each campaign, an LLM is asked to generate ~30 Google search queries based on the campaign's industries, locations, and platforms list. Each query is sent to Google (via Serper API). For each result URL, one of two things happens:

1. **Snippet-hit path (free)** — if the result's snippet already contains a `chat.whatsapp.com/<invite_id>` substring, the pipeline extracts it without fetching the page.
2. **Fetch path (costs a Firecrawl/Reddit credit)** — if the snippet doesn't have the invite, the page is fetched and the regex runs on the full markdown.

So **maximizing snippet-hit rate** is the cheapest way to grow yield. Snippet hits are forced by including the literal exact-phrase `"chat.whatsapp.com"` (with the double quotes) in the query. Google then only returns pages whose visible text contains that exact string — and those pages' snippets almost always contain the full URL.

## The 4 dimensions of a good query

Every Google query in this pipeline can be decomposed into 4 dimensions:

```
QUERY = anchor × industry-term × platform-constraint × geo-constraint
```

| Dimension | Strong narrowing | Weak narrowing | Why |
|---|---|---|---|
| **Anchor** | `"chat.whatsapp.com"` (exact phrase, quoted) | `whatsapp group`, `wa community` | Forces the invite into the snippet so we extract for free |
| **Industry term** | `"SaaS founders"`, `"micro SaaS"` (specific, quoted) | `SaaS owners` (broad, unquoted) | Quoted exact-match cuts Google's index dramatically |
| **Platform constraint** | `site:meetup.com`, `site:reddit.com` | (no `site:`) | Limits the corpus by ~3 orders of magnitude |
| **Geo constraint** | `-india -indian` (exclude), `+Dubai` (include) | (none) | Eliminates off-geo long tail |

**Rule of thumb:** a query without **at least 2 of** {exact-phrase anchor, quoted industry term, `site:` operator} is probably wasting a Serper credit.

The current LLM prompt encourages narrowing but doesn't enforce it. Inspecting actual generated queries shows only ~30–50% include the literal `"chat.whatsapp.com"` and many use unquoted industry phrases.

## Why narrow queries win — the math

A query like:

```
"SaaS owners" whatsapp group
```

matches **millions of pages**. Google has to pick "the most relevant" — which in this case means SEO-optimized listicles ("Top 10 WhatsApp groups for SaaS!"), generic blogs, and aggregator pages. None of those contain real community invite links.

A query like:

```
"chat.whatsapp.com" "SaaS founders" site:meetup.com -india -indian
```

matches **maybe 50 pages globally**. Google has no choice but to return real ones. Three properties make this work:

1. The exact-phrase `"chat.whatsapp.com"` forces the invite into the result's snippet.
2. The exact-phrase `"SaaS founders"` filters out off-topic results.
3. `site:meetup.com` limits to a host that we know yields well and that we can fetch when needed.
4. `-india -indian` removes a known off-geo cluster.

The narrower query costs **the same Serper credit** but yields **dramatically more usable invites**. And because the snippet usually has the full URL, fetching costs are also lower.

So **specificity is approximately inverse of corpus size matched, and yield is approximately proportional to specificity** — for this particular pipeline shape.

## Proposed algorithm redesign

Replace the single "trust the LLM" call with a **2-LLM-call + algorithmic combinator** structure. The LLM is great at vocabulary expansion. It's bad at consistent operator placement across 30 queries — it tries to be "creative" and ends up broad. Move that part into deterministic code.

```
Stage 1A — Industry-term expansion (1 cheap LLM call)
  In:  ICP industries, e.g. ["SaaS"]
  Out: 6–10 specific quoted-able phrasings, e.g.
       ["SaaS founders", "B2B SaaS", "indie SaaS", "micro SaaS",
        "SaaS marketing", "vertical SaaS", "SaaS startup",
        "software entrepreneurs", "SaaS bootstrappers"]
  Budget: ~200 tokens output, $0.0001-ish per campaign.

Stage 1B — Combinatorial template expansion (algorithmic, no LLM)
  Templates ranked by predicted precision:
    T1 (PRECISION):  '"chat.whatsapp.com" "{term}" site:{platform} {-neg}'
    T2 (PRECISION):  '"chat.whatsapp.com" "{term}" {-neg}'    ← open web
    T3 (MEDIUM):     '"{term}" whatsapp group site:{platform} {-neg}'
    T4 (MEDIUM):     '"{term}" join whatsapp invite {-neg}'
    T5 (LOOSE):      '{term} community whatsapp site:{platform}'
  
  Cartesian product over (terms × platforms × templates).
  Dedupe near-misses by lowercase + sorted-tokens.

Stage 1C — Budget allocation
  Total queries = N (default 30, or budget-derived).
  Tier weights:    60% T1+T2  |  30% T3+T4  |  10% T5
  Platform weights (initial, pre-feedback):
    meetup 35% · reddit 30% · eventbrite 15% · open-web 15% · soft 5%
  Pick top-N from each tier × platform bucket.

Stage 1D — Yield feedback (later iteration)
  After campaign completes, log per-template hit rate (leads / query).
  Next campaign for same industry adjusts weights toward what worked
  (Bayesian update). Self-tunes over time.
```

**Why split LLM expansion from query construction:**

- Stage 1A is what LLMs are *good* at — open-ended vocabulary suggestions
- Stage 1B is what LLMs are *bad* at — consistent operator templating across many outputs
- Code does Stage 1B reliably, every query has the same quality of operators
- The cartesian product gives natural variety without needing the LLM to "be creative"

## Two more ideas worth brainstorming later

### Snowball / cohort search

Once you've found a confirmed-good lead at e.g. `meetup.com/AI-Agency-Founders/`, run a follow-up query pass:

- `site:meetup.com "AI Agency"` → finds sister meetup groups in the same niche
- `"AI Agency Founders"` (the verified group name from WA enrichment) → finds *every* place the group is mentioned, often other Reddit/blog/forum threads that contain *more* invite links to similar groups

This effectively turns one good lead into a "graph walk" that exposes adjacent communities. Implementable as a Stage 6.5 between scoring and finalize.

### Native-platform mining instead of Google

For Reddit specifically, skip Google entirely:

- `asyncpraw` directly searches subreddits via `subreddit.search("whatsapp")`
- Density of invites is higher on Reddit's own search than via Google's index of Reddit
- Same pattern works for **YouTube** (Data API), **Telegram** (telethon), and **Discord** (with a bot in target servers)
- Each is free or near-free at modest scale, and avoids the Google snippet bottleneck

These belong as parallel Stage 4 sources alongside Firecrawl, all feeding the same Stage 5 extractor.

## Suggested rollout

**Phase 1 (~half a day):** rewrite stage 1 as the 1A + 1B + 1C structure. Tighten the prompt so 1A produces narrow quoted-able terms. Probably 2–3× more leads per campaign on day one.

**Phase 2 (~half a day):** snowball search — after stage 6 finishes, take the top-10 verified group names and run a single 1B re-pass with those as quoted terms. Adds a graph-walk to the pipeline.

**Phase 3 (~1 day):** Reddit-native via asyncpraw + YouTube via Data API. Each adds a new Stage 4 source feeding into the existing Stage 5 extractor.

**Phase 4 (later):** per-template yield feedback (Stage 1D). Becomes meaningful after ~10 campaigns of data.

## What this changes for the user-facing experience

- Campaigns finish with **more leads** at the same Serper / Firecrawl budget.
- Leads are **more obviously on-target** because narrow queries return precise pages, not aggregator junk.
- The **bottom of the lead list** is also clearer — leads that come through are signal, not "well I guess this might be related" noise.
- No UI changes required. All of this is backend pipeline work.
